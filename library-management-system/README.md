# 📚 Library Management System (LMS)
### Database Management Systems (DBMS) Mini Project

A comprehensive, academic-grade **Library Management System** engineered specifically to satisfy and exceed all standard **Database Management Systems (DBMS)** curriculum requirements. It demonstrates relational schema design, 1NF to BCNF normalization, referential integrity constraints, automated triggers, indexed search, virtual views, ACID-compliant transactions, and complex SQL queries.

---

## 🌟 Key Highlights & DBMS Concepts Implemented

| DBMS Concept | Implementation in this Project |
| :--- | :--- |
| **Relational Data Modeling** | Complete 10-table schema with primary keys, foreign keys, and bridge tables. |
| **Normalization** | Decomposed from UNF to **3NF / BCNF** to eliminate insertion, deletion, and update anomalies. |
| **Integrity Constraints** | `PRIMARY KEY`, `FOREIGN KEY` (`ON DELETE CASCADE` / `RESTRICT` / `SET NULL`), `CHECK` constraints, `UNIQUE`, and `NOT NULL`. |
| **Automated Triggers** | `AFTER INSERT ON loans` automatically decrements available book copies; `AFTER UPDATE OF return_date` restores stock and writes to `audit_logs`. |
| **Virtual Views** | `v_book_catalog`, `v_active_loans`, `v_member_fines`, and `v_category_stats`. |
| **ACID Transactions** | Multi-statement `BEGIN TRANSACTION`, `COMMIT`, and `ROLLBACK` for book issues, returns, and payments. |
| **Performance Indexes** | B-Tree indexes on ISBN, titles, category IDs, loan status, and fine payment states. |
| **Dual Presentation Interfaces** | **Modern Flask Web Dashboard** + **Interactive Terminal CLI** for lab evaluations. |
| **Interactive SQL Playground** | Integrated web query console with 8 pre-loaded academic DBMS queries and `EXPLAIN QUERY PLAN` support. |

## 🚀 Quickstart Guide

### 1. Prerequisites
- Python 3.8 or newer
- SQLite 3 (bundled with Python)
- Flask (`pip install -r requirements.txt`)

### 2. Running the Web Application
To run the full interactive web portal:
```bash
# Method A: Using the startup script
./run.sh

# Method B: Directly with Python
python3 app.py
```
Open your browser and navigate to:
👉 **`http://127.0.0.1:5000`**

### 3. Running the Terminal CLI (For Console Lab Exams)
If your examiner asks for terminal execution:
```bash
./run.sh cli
# or: python3 cli.py
```

### 4. Resetting Sample Data
To return the database back to its clean initial demonstration state:
```bash
./run.sh reset
```
*(Or click the **↻ Reset DB** button in the Web UI navigation bar).*

## 🖥️ Web Interface Features

1. **Dashboard (`/`)**:
   - High-level KPIs: Book Titles, Total Inventory, Active Loans, Overdue Count, Unpaid Fines, Registered Members.
   - Live Trigger Audit Trail: Displays real-time entries generated by SQLite triggers.
   - Subject Categories Inventory breakdown table.
2. **Book Catalog (`/books`)**:
   - Complete list powered by `v_book_catalog` view with aggregated authors.
   - Real-time client-side search across Title, Author, Category, and ISBN.
   - "Add New Book" modal dialog with foreign key validations.
3. **Book Detail View (`/books/<id>`)**:
   - Detailed specifications, author biographies (Many-to-Many relationship), and full borrowing transaction history.
4. **Members Directory (`/members`)**:
   - Student, Faculty, and General members with borrowing quotas and real-time fine balances.
   - Member registration modal with check constraint validation.
5. **Circulation Desk (`/circulation`)**:
   - **Issue Book**: ACID transaction checking membership status, active quota limit, and book stock.
   - **Return Book**: Automatic stock increment via trigger, overdue fine calculation ($5/day past due date).
6. **Fines Management (`/fines`)**:
   - Financial ledger tracking total assessed, collected, and pending fines.
   - One-click fine settlement recording audit timestamps.
7. **Interactive SQL Console (`/sql_console`)**:
   - Pre-loaded academic queries: Correlated subqueries, `GROUP BY ... HAVING`, `NOT EXISTS`, `RANK() OVER`, and `EXPLAIN QUERY PLAN`.
   - Dynamic HTML table renderer for custom `SELECT` queries.

## 📊 Relational Database Design Overview

### Core Tables:
1. `publishers` (`publisher_id`, `name`, `address`, `phone`, `email`)
2. `categories` (`category_id`, `category_name`, `description`)
3. `authors` (`author_id`, `first_name`, `last_name`, `biography`)
4. `books` (`book_id`, `isbn`, `title`, `category_id`, `publisher_id`, `publication_year`, `total_copies`, `available_copies`, `shelf_location`, `price`)
5. `book_authors` (`book_id`, `author_id`) &mdash; *M:N Bridge Table*
6. `members` (`member_id`, `first_name`, `last_name`, `email`, `phone`, `membership_type`, `join_date`, `max_books_allowed`, `status`)
7. `staff` (`staff_id`, `first_name`, `last_name`, `role`, `email`, `phone`)
8. `loans` (`loan_id`, `book_id`, `member_id`, `staff_id`, `issue_date`, `due_date`, `return_date`, `status`)
9. `fines` (`fine_id`, `loan_id`, `fine_amount`, `fine_date`, `paid_status`, `paid_date`)
10. `audit_logs` (`log_id`, `action`, `table_name`, `record_id`, `details`, `timestamp`)
