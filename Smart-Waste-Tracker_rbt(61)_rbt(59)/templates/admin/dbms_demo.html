Implemented Stored Procedures

Stored procedures enforce transactional boundaries, parameter checking, and business logic execution within the database engine.

CALL sp_create_collection_request(p_citizen_id, p_category_id, p_area_id, p_est_quantity, p_address, p_pref_date, p_notes, @out_req_id);

Atomically verifies request is 'Pending', verifies worker availability is 'Available', sets row locks (FOR UPDATE), inserts into assignments, transitions request to 'Assigned', and updates worker availability to 'Busy'.

CALL sp_assign_worker(p_request_id, p_worker_id, p_admin_id);

Enforces valid state transition lifecycle (Pending → Assigned → In Progress → Collected → Completed), manages measured weight inputs, and releases sanitation workers when completed.

trg_before_request_insert

AFTER UPDATE
trg_after_status_change

Fires on collection_requests table. Automatically appends audit tracking entries into collection_status_history whenever status column is changed.

INSERT INTO collection_status_history VALUES (NEW.request_id, OLD.status, NEW.status...);
AFTER UPDATE
trg_after_assignment_complete

Fires on assignments table. When an assignment transitions to Completed, automatically increments the worker's lifetime counter.

UPDATE workers SET total_collections = total_collections + 1...
BEFORE UPDATE
trg_before_request_update

Fires on collection_requests table. Automatically stamps completed_at = NOW() when status becomes Completed.

IF NEW.status = 'Completed' THEN SET NEW.completed_at = NOW();
